## Стек

- **BDD-фреймворк:** Cucumber (via `@cucumber/cucumber`)
- **Тесты:** Vitest (unit + integration)
- **E2E:** Playwright
- **Покрытие:** ≥ 96%

## Фичи ( features )

### landing.feature

```gherkin
Функция: Лендинг и форма заявки

  Предыстория:
    Given пользователь открывает лендинг "/"

  Сценарий: Отображение услуг
    Then на странице отображаются карточки услуг
    And каждая карточка содержит название и описание

  Сценарий: Отправка заявки (happy path)
    When пользователь заполняет поле "Имя" значением "Иван"
    And пользователь заполняет поле "Телефон" значением "+79991234567"
    And пользователь выбирает услугу "Сантехника"
    And пользователь ставит чекбокс согласия на обработку ПД
    And пользователь нажимает кнопку "Отправить заявку"
    Then показывается сообщение "Спасибо! Ваша заявка принята."

  Сценарий: Ошибка валидации — пустое имя
    When пользователь оставляет поле "Имя" пустым
    And пользователь заполняет поле "Телефон" значением "+79991234567"
    And пользователь нажимает кнопку "Отправить заявку"
    Then показывается ошибка "Введите имя"

  Сценарий: Ошибка валидации — неверный формат телефона
    When пользователь заполняет поле "Имя" значением "Иван"
    And пользователь заполняет поле "Телефон" значением "123"
    And пользователь нажимает кнопку "Отправить заявку"
    Then показывается ошибка "Неверный формат телефона"
```

### leads.feature

```gherkin
Функция: Управление заявками

  Предыстория:
    Given в системе есть заявка "LEAD-0001" со статусом "NEW"

  Сценарий: Просмотр списка заявок (админ)
    Given пользователь авторизован как администратор
    When пользователь переходит на страницу "/admin"
    Then в таблице отображается заявка "LEAD-0001"

  Сценарий: Смена статуса заявки
    Given пользователь авторизован как администратор
    When пользователь меняет статус заявки "LEAD-0001" на "CONTACTED"
    Then статус заявки изменяется на "CONTACTED"

  Сценарий: Отзыв клиента
    Given заявка "LEAD-0001" имеет статус "CONVERTED"
    When клиент переходит по ссылке "/feedback?lead=LEAD-0001"
    And клиент ставит рейтинг "5" и комментарий "Отличный сервис"
    And клиент нажимает "Отправить отзыв"
    Then показывается сообщение "Спасибо за отзыв!"
    And рейтинг партнёра увеличивается на 2

  Сценарий: Дедупликация заявки
    When пользователь отправляет заявку с телефоном "+79991234567" и услугой "Сантехника"
    And пользователь отправляет ещё одну заявку с тем же телефоном и услугой
    Then вторая заявка отклоняется с ошибкой 409 "Заявка уже принята"
```

### auth.feature

```gherkin
Функция: Авторизация

  Сценарий: Успешный вход
    Given пользователь зарегистрирован с email "user@example.com" и паролем "password123"
    When пользователь переходит на "/auth/login"
    And пользователь вводит email "user@example.com" и пароль "password123"
    And пользователь нажимает "Войти"
    Then пользователь перенаправляется на дашборд

  Сценарий: Неверный пароль
    Given пользователь зарегистрирован с email "user@example.com"
    When пользователь вводит email "user@example.com" и пароль "wrong"
    And пользователь нажимает "Войти"
    Then показывается ошибка "Неверный email или пароль"

  Сценарий: Корневой суперадмин — первый вход
    Given корневой суперадмин создан с password_hash = NULL
    When суперадмин входит в систему
    Then система требует задать пароль
    When суперадмин задаёт новый пароль
    Then вход выполняется успешно
```

### admin.feature

```gherkin
Функция: Админ-панель

  Предыстория:
    Given пользователь авторизован как администратор региона "Берск"

  Сценарий: Просмотр дашборда
    When пользователь переходит на "/admin"
    Then отображается статистика: число заявок, заявки за сегодня, число партнёров

  Сценарий: Апровал партнёра
    Given есть партнёр "МастерОК" со статусом "pending"
    When админ нажимает "Одобрить" на партнёре "МастерОК"
    Then статус партнёра меняется на "approved"
    And партнёр отображается на лендинге

  Сценарий: Отклонение партнёра
    Given есть партнёр "Подозрительный" со статусом "pending"
    When админ нажимает "Отклонить" на партнёре "Подозрительный"
    Then статус партнёра меняется на "rejected"
    And партнёр не отображается на лендинге

  Сценарий: Фильтрация по региону
    Given в системе есть партнёры из "Берска" и "Иркутска"
    When админ открывает список партнёров
    Then отображаются только партнёры из "Берска"
```

### partner.feature

```gherkin
Функция: Личный кабинет партнёра

  Предыстория:
    Given пользователь авторизован как партнёр "Иван"

  Сценарий: Просмотр дашборда
    When партнёр переходит на "/partner"
    Then отображаются заявки, конверсия, рейтинг

  Сценарий: Получение реферальной ссылки
    When партнёр переходит на "/partner/referral"
    Then отображается ссылка "site.com/?ref=TOKEN"
    And отображается промо-код

  Сценарий: Просмотр приглашённых
    Given партнёр пригласил "Петя" и "Вася"
    When партнёр переходит на "/partner/invites"
    Then отображаются "Петя" и "Вася" в списке
```

### referral.feature

```gherkin
Функция: Реферальная система

  Сценарий: Переход по реферальной ссылке
    When клиент переходит по ссылке "/?ref=TOKEN123"
    Then в cookie сохраняется "ref=TOKEN123" на 30 дней
    And при отправке заявки она привязывается к партнёру с токеном "TOKEN123"

  Сценарий: First-touch атрибуция
    Given клиент уже был по реферальной ссылке "PARTNER_A"
    When клиент переходит по ссылке "PARTNER_B"
    Then заявка по-прежнему привязана к "PARTNER_A"

  Сценарий: Невалидный токен
    When клиент переходит по ссылке "/?ref=INVALID"
    Then источник заявки = "QR" (токен игнорируется)

  Сценарий: Партнёрская рефералка
    Given партнёр "Иван" имеет промо-код "IVAN-PROMO"
    When новый партнёр регистрируется с промо-кодом "IVAN-PROMO"
    Then у нового партнёра `referrer_id` = id партнёра "Иван"
```

### feedback.feature

```gherkin
Функция: Отзывы клиентов

  Сценарий: Успешный отзыв
    Given заявка "QR-0001" имеет статус "CONVERTED"
    When клиент переходит на "/feedback?lead=QR-0001"
    And клиент ставит рейтинг "5"
    And клиент пишет комментарий "Быстро и качественно"
    And клиент нажимает "Отправить отзыв"
    Then показывается "Спасибо за отзыв!"
    And рейтинг партнёра увеличивается на 2

  Сценарий: Негативный отзыв
    Given заявка "QR-0002" имеет статус "CONVERTED"
    When клиент ставит рейтинг "2"
    And клиент нажимает "Отправить отзыв"
    Then рейтинг партнёра уменьшается на 3

  Сценарий: Повторный отзыв
    Given заявка "QR-0001" уже имеет отзыв
    When клиент пытается оставить ещё один отзыв
    Then показывается ошибка "Отзыв уже был оставлен"
```
