# Промпт: Визуальный интерфейс — Сайт-визитка с QR-кодом и реферальной системой

> Связанные документы: [PRD](../prd/README.md) | [Отчёт по полноте PRD](../prd/PRD_completeness_report.md) | [Архитектура](../architecture/README.md) | [Инфраструктура](../infrastructure/README.md) | [План развития](../roadmap/README.md) | [BDD](../bdd/README.md)

## Контекст

Сайт-визитка для сбора заявок с офлайн-носителей (QR-коды на визитках/рекламе) и партнёрских каналов. Пользователь сканирует QR → попадает на лендинг → выбирает услугу → оставляет заявку. Параллельно партнёры получают реферальные ссылки и привлекают клиентов.

Бренд: **ВСЯК** — универсальный справочник услуг для новоселов.

## Стек

- Svelte (SvelteKit или Vite + Svelte)
- UnoCSS (Tailwind-совместимый синтаксис через `@unocss/preset-wind`)
- Mobile-first (QR сканируют с телефона)

## Дизайн-система

Чистый современный вортмарк **«ВСЯК»** — мягкий скруглённый sans-serif, буквы тёмного графитового цвета, последняя буква **«К»** — мягкий голубой (#A5C4E8). Центрирован в верхней части страницы. Элегантный и минималистичный.

## UI-контролы и формы

Реализуй единый механизм UI-контролов, который используется как в административном интерфейсе, так и в пользовательских формах.

Основной принцип: **минимальная сложность и минимальный объём собственного кода**. Не создавать собственную UI-библиотеку или избыточную abstraction layer.

### Архитектура

1. **Native HTML controls** как базовый уровень:
   - `button`, `input`, `textarea`, `select`, `checkbox`, `radio`, `file`, `label`, `form`

2. Поверх native HTML — небольшие переиспользуемые Svelte-компоненты только там, где это действительно необходимо:
   - `Button`, `Input`, `Textarea`, `Select`, `Checkbox`, `RadioGroup`, `Switch`
   - `FormField`, `Form`, `Modal/Dialog`, `Dropdown`, `Tabs`, `Pagination`

3. Не создавать отдельные компоненты для каждого экрана. Компоненты должны быть **generic и переиспользуемыми**.

4. Не дублировать контролы между admin и public UI. Один базовый набор компонентов, разные варианты (`variant`, `size`, `density`).

### Стилизация

Единый механизм design tokens:
- colors, spacing, typography, border radius, shadows
- focus states, disabled states, error states

Стили задаются централизованно. Не использовать inline styles без необходимости.

### Формы

Композиция контролов:

```text
Form
 ├── FormField
 │    ├── Label
 │    ├── Input
 │    ├── Description
 │    └── Error
 ├── FormField
 │    └── Select
 └── FormActions
```

Контрол отвечает только за UI и взаимодействие. Валидация и бизнес-логика — снаружи.

### Состояния контролов

Все интерактивные контролы поддерживают:
- default, hover, focus, active, disabled, readonly
- loading (если применимо), error, success

Keyboard navigation и accessibility — обязательны. Семантический HTML + ARIA где необходимо.

### Headless / сложные контролы

Для компонентов, где native HTML недостаточен (`Dialog`, `Combobox`, `Popover`, `DatePicker` и т.п.), использовать небольшие проверенные Svelte primitives/headless-компоненты.

Предпочтение решениям:
- не навязывающим визуальный дизайн
- хорошо интегрирующимся со стилями
- с accessibility
- с минимальным runtime

Не подключать полноценную UI-библиотеку только ради нескольких простых контролов.

### Ограничение abstraction

Не создавать компоненты «на будущее». Каждый компонент — реальное использование минимум в 2 местах.

Не создавать: `UniversalControl`, `BaseComponent`, `AbstractInput`, `UIManager`, `ControlFactory` и аналогичные избыточные абстракции.

Целевая архитектура:

```text
HTML
  ↓
small reusable Svelte components
  ↓
Form / Admin components
  ↓
Pages
```

### Важно

Перед добавлением UI-библиотеки проверь, можно ли реализовать контрол семантическим HTML + небольшим Svelte-компонентом. Подключать зависимость только если она даёт существенную функциональность, которую сложно реализовать самостоятельно — особенно для интерактивных компонентов с доступностью (accessibility).

## Требования к дизайну

### Mobile-first
- Все элементы — крупные touch-targets (минимум 44×44 px)
- Форма — не более 3 полей (имя, телефон, услуга)
- Телефон — нативная клавиатура (`type="tel"`)
- CTA-кнопка — занимает всю ширину на мобилке
- Адаптация от 320px до 1440px

### Визуал
- Clean, warm, premium, много soft whitespace
- Мягкие тени, скруглённые углы, modern and friendly
- Без резких контрастов (no harsh contrasts)
- Мягкое естественное освещение (soft natural lighting)
- Cream background (#F9F7F2)

### Состояния
- Loading: спиннер на кнопке + заблокированные поля
- Success: анимация появления галочки
- Error: красные рамки на полях + текст ошибки под полем
- Пустое состояние: «Заявок пока нет»
- Партнёр без апровала: серый бейдж «На модерации»

### Доступность
- Все поля формы имеют `<label>` (визуально скрытый, доступный для screen reader)
- Кнопки имеют текст (не только иконки)
- Цвет не единственный индикатор статуса (иконка + текст)
